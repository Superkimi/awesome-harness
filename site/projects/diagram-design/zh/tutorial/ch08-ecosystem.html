    9  # Diagram Design
   10
   11  Create visual diagrams as self-contained HTML files with inline SVG and CSS, following an opinionated editorial design system.
   12
   13  Twenty-seven visual types. Semantic patterns describe behavior independently; type references describe layout. Details load from `references/` only when selected.
   14
   15  ---
   16
   17  ## 0. First-time setup — style guide gate
   18
   19  **Before generating your first diagram in a new project, verify the style guide has been customized.**
   20
   21  Don't silently ship default-skinned diagrams into a branded project.
   22
   23  Open [`references/style-guide.md`](references/style-guide.md) and check the default tokens. If they're still the shipped defaults (paper `#faf7f2`, ink `#1c1917`, accent `#b5523a` rust), **pause and ask the user**:
   24
   25  > *"This is your first Schematic in this project. The style guide is still at the default (neutral stone + rust). Do you want to customize it to match your brand first? Options: (a) pull from your website URL, (b) extract from an installed skill, (c) extract from a local folder / design-system directory, (d) paste tokens manually, (e) proceed with the default for now."*
   26
   27  Then branch:
   28
   29  - **(a)** → follow [`references/onboarding.md § URL`](references/onboarding.md) to fetch the site, extract palette + fonts, propose a diff, and write `style-guide.md`.
   30  - **(b)** → follow [`references/onboarding.md § Skill`](references/onboarding.md) — ask which skill, read its SKILL.md / CSS / token files, map to semantic roles, propose diff.
   31  - **(c)** → follow [`references/onboarding.md § Folder`](references/onboarding.md) — ask for the path, glob for CSS/JSON/MD token files, map to semantic roles, propose diff.
   32  - **(d)** → accept the user's tokens and write them into `style-guide.md` under a new "Custom tokens" section.
   33  - **(e)** → proceed; optionally remind the user they can run onboarding later.
   34
   35  **Once the style guide has been customized** (or the user explicitly opted for default), skip this gate on subsequent runs. A simple way to detect customization: if the `accent` value in `style-guide.md` differs from `#b5523a`, assume custom.
   36
   37  ---
   38
   39  ## 1. Philosophy
   40
   41  **The highest-quality move is usually deletion.**
   42
   43  Applied to schematics:
   44
   45  - Every node represents a distinct idea. Two nodes that always travel together are one node.
   46  - Every connection carries information. If the relationship is obvious from layout, remove the line.
   47  - Coral is **editorial, not a flag.** 1–2 focal nodes per diagram. Using it on 5 nodes erases the signal.
   48  - The schematic isn't done when everything is added. It's done when nothing can be removed.
   49
   50  **Target density: 4/10.** Enough to be technically complete. Not so dense it needs a guide. Above 9 nodes, it's probably two diagrams.
   51
   52  ---
   53
   54  ## 2. When to Use
   55
   56  Use for any of the 27 visual types (§3) when a reader will learn more from a visual than from prose, a table, or a bulleted list.
   57
   58  **Don't use for:**
   59
   60  - Quick unicode diagrams → use **wiretext**.
   61  - Lists of things → table or bullets.
   62  - Simple before/after → table.
   63  - One-shape "diagrams" → just write the sentence.
   64
   65  Before drawing, ask: *Would the reader learn more from this than from a well-written paragraph?* If no, don't draw.
   66
   67  ---
   68
   69  ## 3. Selection: semantic pattern, then visual type
   70
   71  When behavior, state, enforcement, or risk carries the meaning, first load [`references/semantic-patterns.md`](references/semantic-patterns.md) and choose one primary pattern. Then choose the nearest visual type for layout. If no pattern matches, choose the type directly.
   72
   73  | Behavioral trigger | Semantic pattern → nearest type |
   74  |---|---|
   75  | Fan-in, queue depth, finite capacity, bottleneck | **Fan-in queue / bottleneck** → Data flow |
   76  | Repeated Question / Input / Governance / Output slots across stages | **Stage framework with semantic slots** → Process |
   77  | Conversation or loose input becomes a structured durable artifact | **Unstructured input → structured artifact** → Data flow |
   78  | Two rule traces need pass/fail/skipped/not-reached and first divergence | **Paired policy-evaluation traces** → Flowchart |
   79  | Trust boundaries plus permitted/forbidden ingress or deploy paths | **Secure paved road** → Architecture |
   80  | Controls grouped by where they are enforced | **Governance / control catalog** → Layer stack |
   81  | Defenses compensate for prior gaps and residual risk propagates | **Compensating security layers** → Layer stack |
   82
   83  The pattern owns semantic primitives and its tighter budget; the type owns layout grammar. Use [`references/animation.md`](references/animation.md) only when motion is requested or materially clarifies ordered change; static remains the default.

   39  ## 1. Philosophy
   40
   41  **The highest-quality move is usually deletion.**
   42
   43  Applied to schematics:
   44
   45  - Every node represents a distinct idea. Two nodes that always travel together are one node.
   46  - Every connection carries information. If the relationship is obvious from layout, remove the line.
   47  - Coral is **editorial, not a flag.** 1–2 focal nodes per diagram. Using it on 5 nodes erases the signal.
   48  - The schematic isn't done when everything is added. It's done when nothing can be removed.
   49
   50  **Target density: 4/10.** Enough to be technically complete. Not so dense it needs a guide. Above 9 nodes, it's probably two diagrams.

    5  ## Context
    6
    7  `SKILL.md` loads into an agent's context on every skill invocation, so it must stay lean; a byte cap keeps growth honest. The description is the only text an agent sees *before* deciding to load the skill: removing "flowchart", "Gantt", "org chart" from it removes the lexical hooks that make "make me a flowchart" invoke the skill at all.

   10
   11  Two rules, in priority order:
   12
   13  1. The frontmatter `description` must name every visual type in the selection table (enforced by `scripts/verify-docs-sync.py`) plus the import formats and major feature vocabulary. Routing surface is never traded for body prose.

   17
