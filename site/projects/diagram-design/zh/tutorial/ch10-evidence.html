    9  # Diagram Design
   10
   11  Create visual diagrams as self-contained HTML files with inline SVG and CSS, following an opinionated editorial design system.
   12
   13  Twenty-seven visual types. Semantic patterns describe behavior independently; type references describe layout. Details load from `references/` only when selected.
   14
   15  ---
   16
   17  ## 0. First-time setup — style guide gate
   18
   19  **Before generating your first diagram in a new project, verify the style guide has been customized.**
   20
   21  Don't silently ship default-skinned diagrams into a branded project.
   22
   23  Open [`references/style-guide.md`](references/style-guide.md) and check the default tokens. If they're still the shipped defaults (paper `#faf7f2`, ink `#1c1917`, accent `#b5523a` rust), **pause and ask the user**:
   24
   25  > *"This is your first Schematic in this project. The style guide is still at the default (neutral stone + rust). Do you want to customize it to match your brand first? Options: (a) pull from your website URL, (b) extract from an installed skill, (c) extract from a local folder / design-system directory, (d) paste tokens manually, (e) proceed with the default for now."*
   26
   27  Then branch:
   28
   29  - **(a)** → follow [`references/onboarding.md § URL`](references/onboarding.md) to fetch the site, extract palette + fonts, propose a diff, and write `style-guide.md`.
   30  - **(b)** → follow [`references/onboarding.md § Skill`](references/onboarding.md) — ask which skill, read its SKILL.md / CSS / token files, map to semantic roles, propose diff.
   31  - **(c)** → follow [`references/onboarding.md § Folder`](references/onboarding.md) — ask for the path, glob for CSS/JSON/MD token files, map to semantic roles, propose diff.
   32  - **(d)** → accept the user's tokens and write them into `style-guide.md` under a new "Custom tokens" section.
   33  - **(e)** → proceed; optionally remind the user they can run onboarding later.
   34
   35  **Once the style guide has been customized** (or the user explicitly opted for default), skip this gate on subsequent runs. A simple way to detect customization: if the `accent` value in `style-guide.md` differs from `#b5523a`, assume custom.
   36

   39  ## 1. Philosophy
   40
   41  **The highest-quality move is usually deletion.**
   42
   43  Applied to schematics:
   44
   45  - Every node represents a distinct idea. Two nodes that always travel together are one node.
   46  - Every connection carries information. If the relationship is obvious from layout, remove the line.
   47  - Coral is **editorial, not a flag.** 1–2 focal nodes per diagram. Using it on 5 nodes erases the signal.
   48  - The schematic isn't done when everything is added. It's done when nothing can be removed.
   49
   50  **Target density: 4/10.** Enough to be technically complete. Not so dense it needs a guide. Above 9 nodes, it's probably two diagrams.
   51
   52  ---
   53
   54  ## 2. When to Use
   55
   56  Use for any of the 27 visual types (§3) when a reader will learn more from a visual than from prose, a table, or a bulleted list.
   57
   58  **Don't use for:**
   59
   60  - Quick unicode diagrams → use **wiretext**.
   61  - Lists of things → table or bullets.
   62  - Simple before/after → table.
   63  - One-shape "diagrams" → just write the sentence.
   64
   65  Before drawing, ask: *Would the reader learn more from this than from a well-written paragraph?* If no, don't draw.
   66

   69  ## 3. Selection: semantic pattern, then visual type
   70
   71  When behavior, state, enforcement, or risk carries the meaning, first load [`references/semantic-patterns.md`](references/semantic-patterns.md) and choose one primary pattern. Then choose the nearest visual type for layout. If no pattern matches, choose the type directly.
   72
   73  | Behavioral trigger | Semantic pattern → nearest type |
   74  |---|---|
   75  | Fan-in, queue depth, finite capacity, bottleneck | **Fan-in queue / bottleneck** → Data flow |
   76  | Repeated Question / Input / Governance / Output slots across stages | **Stage framework with semantic slots** → Process |
   77  | Conversation or loose input becomes a structured durable artifact | **Unstructured input → structured artifact** → Data flow |
   78  | Two rule traces need pass/fail/skipped/not-reached and first divergence | **Paired policy-evaluation traces** → Flowchart |
   79  | Trust boundaries plus permitted/forbidden ingress or deploy paths | **Secure paved road** → Architecture |
   80  | Controls grouped by where they are enforced | **Governance / control catalog** → Layer stack |
   81  | Defenses compensate for prior gaps and residual risk propagates | **Compensating security layers** → Layer stack |
   82
   83  The pattern owns semantic primitives and its tighter budget; the type owns layout grammar. Use [`references/animation.md`](references/animation.md) only when motion is requested or materially clarifies ordered change; static remains the default.
   84
   85  ### Visual-type guide (27)
   86
   87  | If you're showing… | Use | Reference |
   88  |---|---|---|
   89  | Components + connections in a system | **Architecture** | [type-architecture.md](references/type-architecture.md) |
   90  | Legacy IT landscape grouped by phase/department; documents the *before* state in modernization proposals | **IT current-state** | [type-it-state.md](references/type-it-state.md) |
   91  | Decision logic with branches | **Flowchart** | [type-flowchart.md](references/type-flowchart.md) |
   92  | Time-ordered messages between actors | **Sequence** | [type-sequence.md](references/type-sequence.md) |

  131  ## 4. Universal Anti-patterns
  132
  133  These mark "AI slop" schematics of any type:
  134
  135  | Anti-pattern | Why it fails |
  136  |---|---|
  137  | Dark mode + cyan/purple glow | Looks "technical" without design decisions |
  138  | JetBrains Mono as blanket "dev" font | Mono is for *technical* content — ports, commands, URLs. Names go in Geist sans. |
  139  | Identical boxes for every node | Erases hierarchy |
  140  | Legend floating inside the diagram area | Collides with nodes |
  141  | Arrow labels with no masking rect | Bleeds through the line |
  142  | Vertical `writing-mode` text on arrows | Unreadable |
  143  | 3 equal-width summary cards as default | Generic grid — vary widths |
  144  | Shadow on any element | Shadows are out. Borders are in. |
  145  | `rounded-2xl` on boxes | Max radius 6–10px or none |
  146  | Coral on every "important" node | Coral is 1–2 editorial accents, not a signaling system |
  147  | Reproducing Mermaid's renderer layout | Imports automatic spacing and routing instead of making an editorial layout |
  148  | Diagonal / slanted connectors between off-axis nodes | Rounded right-angle (orthogonal) elbows are mandatory — see §6 Mandatory connector rules |
  149  | Arrow label sitting on or touching its connector | Label must have a 6–10px gap above the line so the connector stays visible |
  150  | Two connectors overlapping or running on the same path | Each connection must be independently traceable — bridge crossings, offset parallels |
  151  | Two connectors sharing a single attach point on a box | Fan attach points along the edge (≥12px apart) so every arrow is clearly distinct — see §6 rule 4 |
  152  | Connector routed behind a non-endpoint box without need | Reroute around intervening boxes; the dashed-transit exception (§6 rule 5) only applies when an unavoidable intervening box sits on the direct path |
  153
  154  Type-specific anti-patterns live in each `references/type-*.md`.

  158  ## 5. Design System
  159
  160  **The design system is skinnable.** All colors, typography, and tokens live in a single source of truth — [`references/style-guide.md`](references/style-guide.md). This file describes semantic roles (`paper`, `ink`, `muted`, `accent`, `link`, …). The default skin is a cool editorial palette (white-smoke paper, jet-black ink, atomic-tangerine accent, blue-slate muted, silver hairlines); to apply your own brand, either edit `style-guide.md` directly or run the URL-based flow described in [`references/onboarding.md`](references/onboarding.md).
  161
  162  > When specs below or in type references mention "ink", "accent", "muted", etc., look up the current hex value in `style-guide.md`.
  163
  164  ### Semantic roles (at a glance)
  165
  166  | Role | Purpose |
  167  |---|---|
  168  | `paper`, `paper-2` | Page bg and container bg |
  169  | `ink` | Primary text / stroke |
  170  | `muted`, `soft` | Secondary text, default arrows, sublabels |
  171  | `rule`, `rule-solid` | Hairline borders |
  172  | `accent`, `accent-tint` | 1–2 focal elements per diagram |
  173  | `link` | HTTP/API calls, external arrows |
  174
  175  **Focal rule:** `accent` goes on 1–2 elements max. Everything else is `ink` / `muted` / `soft`. If you're tempted to accent 4 things, you haven't decided what's focal yet.
  176
  177  ### Node type → treatment
  178
  179  | Type | Fill | Stroke |
  180  |---|---|---|
  181  | **Focal** (1–2 max) | `accent-tint` | `accent` |
  182  | **Backend / API / Step** | white | `ink` |
  183  | **Store / State** | `ink @ 0.05` | `muted` |
  184  | **External / Cloud** | `ink @ 0.03` | `ink @ 0.30` |
  185  | **Input / User** | `muted @ 0.10` | `soft` |
  186  | **Optional / Async** | `ink @ 0.02` | `ink @ 0.20` dashed `4,3` |
  187  | **Security / Boundary** | `accent @ 0.05` | `accent @ 0.50` dashed `4,4` |
  188
  189  ### Typography (summary — full spec in style-guide.md)
  190
  191  - **Title** — Instrument Serif, 1.75rem, 400 — H1 only
  192  - **Node name** — Geist (sans), 12px, 600 — human-readable labels
  193  - **Sublabel** — Geist Mono, 9px — ports, URLs, field types
  194  - **Eyebrow / tag** — Geist Mono, 7–8px, uppercase, tracked — type tags, axis labels
  195  - **Arrow label** — Geist Mono, 8px — annotation on arrows
  196  - **Editorial aside** — Instrument Serif *italic*, 14px — callouts only
  197
  198  **Mono is for technical content.** Names are Geist sans. Page title is Instrument Serif. Italic Instrument Serif is reserved for annotation callouts. Never JetBrains Mono as a blanket "dev" font.
  199
  200  ```html
  201  <link href="https://fonts.googleapis.com/css2?family=Instrument+Serif:ital@0;1&family=Geist:wght@400;500;600&family=Geist+Mono:wght@400;500;600&display=swap" rel="stylesheet">
  202  ```
