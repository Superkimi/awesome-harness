    9  # Skill Multi-Injection
   10
   11  ## Report
   12
   13  **What was built** — The `cmd.source === "skill"` non-subtask branch of
   14  `SessionPrompt.command` no longer emits a `<skill_content>` part. Skill bodies
   15  now have exactly one injector: the mention scan in `insertReminders`, which
   16  detects the invoked skill from the leading `/${input.command}` token of the
   17  visible text part. `insertReminders` itself is unchanged — its `alreadyWrapped`
   18  guard keeps its real job (stopping step 2+ from restacking step 1's blocks) and
   19  loses only its obsolete job (avoiding a double wrap with the command path).
   20
   21  Because both sources of skills now flow into one `mentioned` list, the
   22  `MAX_AUTOLOAD = 3` budget and the `mentioned.length >= 2` orchestration reminder
   23  count them uniformly, with no reconciliation logic. `/a ... /b` injects both
   24  bodies plus the orchestration reminder; four or more mentions overflow to the
   25  Skill-tool hint as before.
   26
   27  Test hygiene was fixed alongside: five skill-related test files were writing
   28  `MIMOCODE_DISABLE_*_SKILLS` at module scope, leaking into every file scheduled
   29  later in the same `bun test` process. They now share a `withEnv` helper
   30  (`test/lib/env.ts`) that applies flags in `beforeAll` and restores them in
   31  `afterAll`.

   54  **Journey log**
   55
   56  1. The bug was reproduced live in the authoring session itself: a message of the
   57     form `/compose-next … /mimocode-docs …` delivered only the first skill's body.
   58     The agent's own context was the evidence.
   59  2. The first design considered turning `alreadyWrapped` into a per-name set so
   60     both injectors could coexist. Rejected: it keeps two injectors in sync by
   61     hand, and the `MAX_AUTOLOAD` budget plus the orchestration-reminder count both
   62     have to be reconciled manually — exactly the drift that caused the bug.
   63  3. What made the smaller fix safe was `prompt.ts:4182-4183`: skills already skip
   64     the `$1..$N` / `$ARGUMENTS` template machinery, and the command path wrapped
   65     the raw `templateCommand`, byte-identical to the `info.content` the scan
   66     injects. Deleting the wrap therefore loses nothing. Zero of the 22 bundled
   67     skills use `$ARGUMENTS` or `` !`bash` ``.
   68  4. Do not delete the whole branch: the `visibleText` part must stay, because the
   69     scan's only handle on the invoked skill is its leading `/name` token.
   70  5. Injection correctness now depends on a regex over rendered text rather than a
   71     registry lookup, so non-slug skill names (`skill/index.ts:30` accepts any
   72     string) silently inject nothing. Accepted by explicit user decision — skills
   73     are expected to use standard slugs.
   74
   75  ## [S1] Problem
   76
   77  When a user message begins with a skill slash-invocation and mentions a second
   78  skill later in the same message, only the first skill's body is injected. The
   79  second one survives as literal text and the model never sees its `SKILL.md`.
   80
   81  Reproduction: send `/compose-next 分析一下 ... /mimocode-docs 例如 ...`. The
   82  model receives one `<skill_content name="compose-next">` block, no
   83  `<skill_content name="mimocode-docs">` block, and no multi-skill orchestration
   84  reminder.
   85
   86  Root cause is two independent injection points:
   87
   88  1. **Command path.** `packages/opencode/src/cli/cmd/tui/component/prompt/index.tsx:1169-1177`
   89     routes any input starting with `/` by resolving only the first token of the
   90     first line as a command name. Skills are registered as commands
   91     (`packages/opencode/src/command/index.ts:264-276`, `source: "skill"`), so
   92     `/compose-next` matches and everything after it — including
   93     `/mimocode-docs` — becomes `arguments`. Server-side,
   94     `packages/opencode/src/session/prompt.ts:4259-4269` emits a visible text part
   95     plus one `<skill_content>` part for `input.command` only.
