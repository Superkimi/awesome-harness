    5  ## 摘要
    6
    7  MiMoCode 在共享 Session 引擎上运行 GPT/Codex 模型，同时向它们暴露一套更小的 Codex 风格工具 ABI：`bash`、`apply_patch`、`view_image` 和 `exec`。`exec` 在 QuickJS 中组合经过授权的宿主工具；权限、路径、子进程、取消、持久化和 UI 始终由宿主控制。
    8
    9  ## 核心设计
   10
   11  MiMoCode 没有为 GPT 新建一套 Agent 引擎，而是在统一 Session runtime 上做三件事：
   12
   13  1. 使用 GPT/Codex 专属 system prompt，约定工具选择和调度方式；
   14  2. 通过 `ToolRegistry` 装配更小的模型专属工具 ABI；
   15  3. 提供 QuickJS `exec`，在不扩大权限的前提下组合宿主工具。
   16
   17  ```mermaid
   18  flowchart LR
   19      Model[GPT / Codex] --> Registry[SystemPrompt + ToolRegistry]
   20      Registry --> Direct[bash / apply_patch / view_image]
   21      Registry --> Exec[exec / QuickJS]
   22      Exec --> Tools[Filtered host tools]
   23      Direct --> Host[Permission + path guards]
   24      Tools --> Host
   25      Host --> Effects[Filesystem / Shell / MCP]
   26      Effects --> Session[SessionProcessor / MessageV2 / TUI]
   27  ```
   28
   29  核心原则是：
   30
   31  > 模型决定做什么，`exec` 负责如何组合，宿主决定是否允许以及如何产生副作用。

   33  ## GPT 工具 ABI
   34
   35  [`ToolRegistry.available()`](../../packages/opencode/src/tool/registry.ts#L363) 当前通过模型 ID 判断是否启用 GPT profile：ID 包含 `gpt-`，同时排除 `oss` 和 `gpt-4`。
   36
   37  | GPT 可见工具 | 作用 |
   38  | --- | --- |
   39  | `bash` | 使用 `rg`、`sed` 等检查和搜索文件，并执行命令 |
   40  | `apply_patch` | 以结构化 patch 修改文本文件 |
   41  | `view_image` | 将本地 JPEG、PNG、GIF、WebP 转为模型附件 |
   42  | `exec` | 在 QuickJS 中批量调用和聚合宿主工具 |
   43
   44  GPT profile 会隐藏能力重叠的 `read`、`write`、`edit`、`multiedit`、`grep`、`glob` 和 `notebook_edit`。其他工具仍按 provider、agent allowlist 和运行时 permission 治理。
   45
   46  [`SystemPrompt.provider()`](../../packages/opencode/src/session/system.ts#L24) 独立选择 `gpt.txt`、`codex.txt` 或 `beast.txt`。Prompt 路由与工具 profile 目前是两套字符串规则，尚未统一成模型能力协商层。
   47
   48  ## `exec` 微内核
   49
   50  [`ToolScriptTool`](../../packages/opencode/src/tool/tool-script.ts#L303) 对模型暴露为 `exec`。模型提交一个 TypeScript/JavaScript async function body，通过 `tools.<name>()` 调用宿主工具。
   51
   52  ### 为什么不会绕过权限
   53
   54  [`tool-script-ref.ts`](../../packages/opencode/src/tool/tool-script-ref.ts#L1) 使用 late-bound registry，让 `exec` 取得和外层相同、已经过 model/agent 过滤的 `Tool.Def`：
   55
   56  - 外层不可见的 `read`、`write`、`edit` 不会在 `exec` 内重新出现；
   57  - builtin 子调用执行原来的 `Tool.Def.execute()` 和 `Tool.Context`；
   58  - MCP 子调用仍逐次执行 `ctx.ask()`；
   59  - `exec_command` 只是 `bash` 的别名，权限和执行路径相同。
   60
   61  `task`、`actor`、`question`、`skill`、`workflow`、`cron`、`session` 等控制流工具被排除，因为它们改变对话或调度状态，不适合隐藏在一次脚本调用中。
   62
   63  ### 两层安全边界
   64
   65  1. [`evalScript()`](../../packages/opencode/src/workflow/sandbox.ts#L106) 用 QuickJS 隔离 guest code，不提供 Node、`process`、`fetch`、timer 或模块加载；
   66  2. 真正副作用仍由宿主工具执行，并经过 permission、external-directory、memory guard 和工具自身校验。
   67
   68  QuickJS 只隔离 `exec` 代码。`bash` 仍是真实 Shell，不是容器 sandbox。
   69
   70  ### 资源限制
   71
   72  | 资源 | 默认值 / 上限 |
   73  | --- | --- |
   74  | 嵌套工具调用 | 默认 50，最高 500 |
   75  | 并发调用 | 8 |
   76  | 活跃计算 | 默认 60 秒，最高 600 秒 |
   77  | Wall clock | 30 分钟 |
   78  | Guest 内存 | 默认 64 MiB |
   79  | 代码 / 返回值 / 日志 | 128 KiB / 256 KiB / 64 KiB |
   80  | `files.*` 单文件 | 10 MiB |
   81
   82  `files.readText` 只能读取 worktree 或 OS tmp 内的 UTF-8 文本；`files.writeText` 只能写 OS tmp。项目变更必须调用受权限控制的宿主工具。

   84  ## 其他关键原语
   85
   86  ### `apply_patch`
   87
   88  [`ApplyPatchTool`](../../packages/opencode/src/tool/apply_patch.ts#L24) 在写入前解析所有 hunks、检查路径、计算 diff 并请求 `edit` permission；写入后发布文件事件、运行格式化并刷新 LSP。
   89
   90  它会预验证全部 patch，但多文件写入不是事务性的，中途失败不会自动回滚已写文件。
   91
   92  ### `view_image`
   93
   94  [`ViewImageTool`](../../packages/opencode/src/tool/view-image.ts#L23) 检查模型 image capability、external-directory 和 `read` permission，再验证图片格式并返回 data URL attachment。
   95
   96  当前限制：
   97
   98  - `detail` 只写入 metadata，不改变图片处理；
   99  - 没有独立的图片大小限制；
  100  - `exec` 只传递文本、metadata 和 JSON 值，不能透传图片 attachment，因此图片应直接调用 `view_image`。

  103
  104  OpenAI provider 通过 [`sdk.responses(modelID)`](../../packages/opencode/src/provider/provider.ts#L203) 发送请求。[`ProviderTransform.options()`](../../packages/opencode/src/provider/transform.ts#L1275) 默认设置 `store: false`，并为 GPT-5 reasoning 模型请求 `reasoning.encrypted_content`。

   38    const m = a.length, n = b.length
   39    if (m === 0) return n
   40    if (n === 0) return m
   41    const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0))
   42    for (let i = 0; i <= m; i++) dp[i][0] = i
   43    for (let j = 0; j <= n; j++) dp[0][j] = j
   44    for (let i = 1; i <= m; i++) {
   45      for (let j = 1; j <= n; j++) {
   46        const cost = a[i - 1] === b[j - 1] ? 0 : 1
   47        dp[i][j] = Math.min(dp[i - 1][j] + 1, dp[i][j - 1] + 1, dp[i - 1][j - 1] + cost)
   48      }
