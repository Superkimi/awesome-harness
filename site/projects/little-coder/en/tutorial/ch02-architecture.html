SOURCE FACT

launcher 按 bundled、LITTLE_CODER_EXTRA_EXTENSIONS、用户扩展目录的顺序加载，后者可覆盖前者；默认传 --no-extensions 禁止 pi 自动发现，只有 --with-pi-extensions 才开启且由 pi 对项目扩展做 trust prompt。

IMPLICATION

这是“小模型少即是多”的插件治理取舍。

L1factmodelContext

03 · 80% 中途压缩 watchdog 补上 pi 的长自主运行缺口

SOURCE FACT

每个 turn_start 读取 live context usage，默认 80% 触发 ctx.compact；完成后自动发送继续消息。它用 in-flight guard、5% 滞回与效果测量防止重复压缩陷入 Nothing to compact。

PLAIN LANGUAGE

模型若连续几十轮调用工具、不把控制权还给用户，原生 pi 可能迟迟不压缩；这个扩展在每一小轮都看油表，快满了就主动整理上下文再接着做。

IMPLICATION

长自治任务的上下文治理不能只挂在用户轮边界。

    3  // Mid-run context watchdog (issue #59).
    4  //
    5  // pi only evaluates auto-compaction at a *user-turn boundary* — its
    6  // `_checkCompaction` runs inside `_handlePostAgentRun`, which fires only after
    7  // `agent.prompt()` has fully returned (i.e. once the model stops requesting
    8  // tools and goes idle). During one long autonomous run this boundary is never
    9  // reached: little-coder's small models routinely chain dozens of tool-call
   10  // turns before yielding, so context grows unchecked and can blow straight past
   11  // the window — pi then only reacts to the *overflow error* after the fact.
   12  // charly1r reproduced exactly this: context climbing 34k → 40k → … → 64k across
   13  // many `slot release` turns with no compaction until the request overflowed.
   14  //
   15  // pi does expose the levers to fix this from an extension: `ctx.getContextUsage()`
   16  // reports live token usage against the active model's window, and `ctx.compact()`
   17  // triggers pi's own compaction without awaiting it. This extension watches usage
   18  // at every turn boundary and, once it crosses a threshold, proactively kicks off
   19  // compaction — so a long single run compacts *before* it overflows, at roughly
   20  // the same point pi would have if the model had yielded.
   21  //
   22  // Tuning / opt-out:
   23  //   LITTLE_CODER_COMPACT_AT_PERCENT   trigger threshold, percent of the context
   24  //                                     window (default 80). <=0 or >=100 disables.
   25  //   LITTLE_CODER_NO_COMPACT_WATCHDOG=1  hard off.
   26  //
   27  // This is complementary to pi's end-of-run compaction, not a replacement — the
   28  // `compacting` guard below keeps us from re-firing while a compaction is already
   29  // in flight, and pi's own threshold/overflow paths still run at run boundaries.
   30  //
   31  // ── Compaction-loop guard (issue #68) ──────────────────────────────────────
   32  // charly1r + Qm-jmz hit an unrecoverable state: after a mid-run compaction the
   33  // resumed model re-reads project files, context climbs back over the threshold,
   34  // the watchdog fires compact() *again* — but now the only summarizable slice is
   35  // the tiny post-compaction tail, so pi's prepareCompaction returns nothing and
   36  // throws "Nothing to compact". Because pi's compact() aborts & disconnects the
   37  // agent *before* that check, the failed second compaction leaves the session
   38  // wedged (nothing the user types recovers it). The same failure mode was traced
   39  // upstream in oh-my-pi#4786 / fixed in oh-my-pi#5448; the deep fix (elide-rescue
   40  // then re-prepare) belongs in pi itself, which little-coder only wraps.
   41  //
   42  // The wrapper-side guard here breaks the LOOP so the session never reaches that
   43  // wedged state: after each compaction we measure the first known post-compaction
   44  // usage, and if it's still at/above the threshold (compaction freed too little)
   45  // we PAUSE automatic compaction and tell the user, instead of firing a doomed
   46  // second compact(). It re-arms automatically once usage drops back below the
   47  // threshold (a manual /clear, /compact, or a genuinely smaller turn). A failed
   48  // compaction (onError, e.g. a "Nothing to compact" that still slips through)
   49  // pauses the same way rather than silently retrying. The deep fix — detect the
   50  // incompressible tail and elide-rescue before giving up — belongs in the pi
   51  // runtime little-coder wraps and has been flagged upstream.
   52
   53  export interface ContextUsageLike {
   54    tokens: number | null;
   55    contextWindow: number;
   56    percent: number | null;
   57  }
   58
   59  const DEFAULT_PERCENT = 80;
   60
   61  // How many percentage points of headroom a compaction must open up to count as
   62  // "made progress". If a compaction leaves usage within this margin of the
   63  // threshold (or still above it), firing again would only try to summarize the
   64  // tiny post-compaction tail — the exact futile path that ends in "Nothing to
   65  // compact" (issue #68). Also the hysteresis band for re-arming after a pause.
   66  export const MIN_PROGRESS_PCT = 5;
   67
   68  // Did the just-finished compaction open up enough headroom to keep going, or is
   69  // automatic compaction now futile (→ pause)? `postPercent` is the first known
   70  // usage reading after the compaction. It "helped" only if usage now sits at
   71  // least MIN_PROGRESS_PCT below the threshold; still at/above the threshold (or
   72  // only a hair under) means the next fire would just try to summarize the tiny
   73  // post-compaction tail — the futile path that ends in "Nothing to compact"
