01 · 子 Agent 支持后台执行、恢复、深度限制与 worktree 隔离

SOURCE FACT

task/spawn_subagent 默认后台运行；启动前校验类型白名单和 toggle，能力取父子交集；可选创建独立 Git worktree，持久化子会话并从 snapshot 恢复；达到 max depth 后移除子 Agent 的 task 工具。

PLAIN LANGUAGE

它是真正的多 Agent 调度：子任务可以后台跑、以后接着跑、在独立分支目录里改代码，但不能无限生孩子。

IMPLICATION

并行协作能力强，同时引入 worktree 生命周期、结果合并、成本与递归治理的高复杂度。

    4  //! ## Tool name resolution
    5  //!
    6  //! All tool names in these prompts use the `${{ tools.by_kind.* }}` template
    7  //! syntax from the `TemplateRenderer`. When the prompt is rendered via
    8  //! `PromptContext::render()` → `ToolBridge::render_prompt()`, MiniJinja
    9  //! resolves each variable to the current session's tool names.
   10  //!
   11  //! This means:
   12  //! - Tool names are NEVER hardcoded — they adapt to name overrides and
   13  //!   alternate tool namespaces
   14  //! - If a tool kind is absent from the renderer's context, MiniJinja
   15  //!   resolves it to an empty string (templates can also use
   16  //!   `${%- if tools.by_kind.X %}` conditionals to hide entire sections)
   17  //!
   18  //! Tool-kind mapping (common names → ToolKind):
   19  //!   Read       → `${{ tools.by_kind.read }}`
   20  //!   Write/Edit → `${{ tools.by_kind.edit }}`

   22  //!   Grep       → `${{ tools.by_kind.search }}`
   23  //!   Bash       → `${{ tools.by_kind.execute }}`
