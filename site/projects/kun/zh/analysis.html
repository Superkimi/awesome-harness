Kun 把 Direct 模式、Agent Graph、工作流运行时、扩展 API、权限和本地恢复放进一个桌面 Agent。它的核心学习点是：复杂任务不是多喊几个模型，而是把节点状态、取消、审批、恢复和插件契约做成一套运行时。

   13  | **Loop（循环）节点** | 工作流里的**一个节点**，把另一个「创建loop」当成**循环体反复执行**。本文讲的就是它。 |
   14  | **运行创建loop（子工作流）节点** | 把另一个「创建loop」**只跑一次**（不循环、不反馈）。 |
   15
   16  一句话区分：**子工作流 = 跑一次；Loop 节点 = 反复跑 + 把结果折回去（或对一组元素各跑一遍）。**
   17
   18  ---
   19
   20  ## 核心思想：循环驱动 agent，而不是人驱动 agent
   21
   22  传统的对话式 agent 是这样的：
   23
   24  ```
   25  你打字 → agent 回答 → 你读 → 你决定下一步 → 你再打字 → …
   26  ```
   27
   28  注意循环在哪儿：**循环在「你」身上**。每一轮都靠你坐在那儿、读完结果、按回车把它推到下一轮。agent 只是被你一次次手动喂的那只手。
   29
   30  Loop 节点把这件事**反过来**。你不再一轮一轮地催，而是**一次性声明三件事**：
   31
   32  1. **每轮要干的活（目标）** —— 循环体，本身是一个完整的「创建loop」，里面可以有 AI 节点、条件判断、HTTP、代码等任意节点。
   33  2. **每轮的输出怎么喂回下一轮** —— 上一轮 output 自动变成下一轮 input。
   34  3. **什么时候算完** —— 一个停止条件，外加 `maxIterations` 作为兜底硬顶。
   35
   36  声明完，循环就**自己转**：agent 在「干活 → 看结果 → 再干活」的圈里自走，不需要你在每一轮按回车。
   37
   38  > **一句话：你设目标 + 每轮的活 + 何时算完，剩下交给循环。**
   39
   40  这正是把你本来要**手动重复输入**的那些催促——“再试一次”“现在把 lint 错误修了”“一直跑到测试过”——**一次写成规则，让它无人值守地跑**。这也是整个功能为什么叫「创建loop」：核心赌注就是，agent 工作的未来形态是**声明一个循环（目标 + 循环体 + 停止条件）**，而不是守着聊天框一轮一轮地敲。
   41
   42  ### 为什么"迭代"才是 agent 真正的形状
   43
   44  - 单次 prompt → 单次回答，是**问答**。
   45  - 把输出折回输入、直到收敛，是**迭代**。
   46
   47  agent 真正干活时几乎都是迭代：草稿 → 自审 → 改稿；跑 → 报错 → 修；调工具 → 不满足 → 再调。Loop 节点把"迭代"变成画布上的**一等公民**——而且因为循环体是一个完整工作流，**"一轮"可以任意复杂**，不是只重复一个节点。
   48
   49  ---
   50
   51  ## 两种循环形态
   52
   53  Loop 节点有两个 `mode`，对应两种完全不同的迭代意图。
   54
   55  ### 1. 条件循环（Condition / loop-agent）—— 反复打磨直到达标
   56
   57  意图：**“一直干到目标满足”**。每一轮把循环体的输出当作下一轮的输入，满足停止条件就停；否则一直到 `maxIterations` 兜底停。
   58
   59  - **停止条件**：`leftExpr` / `operator` / `rightValue` / `caseSensitive`，复用 condition 节点那一套判断。默认是 `json.done` `equals` `true`。
   60  - **反馈**：上一轮 `output` → 下一轮 `payload`，所以循环体能在上一轮基础上继续推进。
   61  - **输出**：循环体最后一轮的 json，外加两个元字段——
   62    - `_iterations`：实际跑了几轮；
   63    - `_done`：`true` = 停止条件达成；`false` = 没达成、是被 `maxIterations` 兜底截停的。
   64  - **节点 message**：`looped N (done)` 或 `looped N (max)`。
   65
   66  这就是 **loop-agent**：像一个人不断 refine 直到自己满意，只是把"满意"交给停止条件来判定，把"再来一轮"交给循环来推动。
   67
   68  > 例：**研究循环**。循环体 = 一个 AI 节点（读资料、补充结论、自评是否够了），停止条件 = `json.enough == true`，`maxIterations = 6`。agent 自己读、自己判断够不够、不够就再来一轮，够了或到 6 轮就停。
   69
   70  ### 2. 遍历数组（For each）—— 同样的活，对每个元素干一遍
   71
   72  意图：**“对列表里每个元素，各跑一遍循环体”**。这是**批处理**，不是打磨——元素之间互不反馈。
   73
   74  - **数组来源**：`arraySource` 表达式；留空则用上游 `payload.json`（要求是数组）。
   75  - **执行方式**：`sequential`（一个接一个）/ `parallel`（同时跑，`concurrency` 并发 1–8）。**并行也保证输出顺序与输入一致。**
   76  - **出错策略**：`continueOnError`
   77    - 打开：某个元素出错就把它记成 `{ error: "..." }`、跳过、继续跑其余元素（**韧性**）；
   78    - 关闭（默认）：一旦有元素出错，立即中止、整个 Loop 节点报错（**fail-fast**）。
   79  - **输出**：每个元素结果组成的数组。**节点 message**：`foreach 成功数/总数`（并行时带 `(parallel)`）。
   80
   81  > 例：对 50 个文件**各跑一遍** “AI 总结”，`parallel`、`concurrency = 4`、`continueOnError = on`，最后拿到 50 条结果（出错的那条是 `{error}`）。
   82
   83  ---
   84
   85  ## 循环体里能用的变量：`$loop`
   86
   87  循环体里**任意节点**都能用 `{{ }}` 插值引用当前这一轮的上下文：
   88
   89  | 变量 | 含义 |
   90  | --- | --- |
   91  | `{{$loop.index}}` | 当前轮 / 当前元素的下标（从 0 开始） |
   92  | `{{$loop.item}}` | 当前元素（foreach）；条件循环里是**上一轮输出的 json** |
   93  | `{{$loop.total}}` | 总数（foreach = 数组长度；条件循环 = `maxIterations`） |
