L1factmodelContext

01 · Provider 不是单一 OpenAI 兼容层，而是多协议适配矩阵

SOURCE FACT

内建 provider registry 装配 Anthropic、OpenAI/Codex/Azure、Google/Vertex、Bedrock、Mistral、Kimi/Moonshot、OpenRouter、GitHub Copilot、xAI 等数十个 provider；API 目录分别实现 messages、responses、chat completions、Gemini、Bedrock 和 pi-messages 协议。

PLAIN LANGUAGE

每家模型的方言由独立翻译器处理，而不是假设所有服务都说 OpenAI 方言。

IMPLICATION

覆盖面很广，也意味着协议行为和 usage/tool schema 回归成本高。

L1factmodelContext

02 · Provider 可热注册和覆盖，失败时退回内建组合

SOURCE FACT

ModelRuntime 合并内建、文件配置、原生扩展配置和 extension provider；扩展可注册模型、OAuth 与自定义 stream。组合错误会保留诊断并回退 builtin，而不是让整个模型目录不可用。

PLAIN LANGUAGE

扩展可以接入私有模型甚至替换流协议；某个扩展写坏时，内置模型仍尽量可用。

IMPLICATION

插件化 provider 适合企业网关，但必须把最终解析来源和错误显式展示。

L1factmodelContext

03 · 传输重试与会话重试分层，上下文溢出单独处理

SOURCE FACT

AI provider retry 解析 status、retry-after 和 headers，使用带 jitter 的可中止等待且单次上限 60 秒；AgentSession 把 transient error 与 quota/billing/overflow 分开，overflow 不进入普通指数退避。

PLAIN LANGUAGE

HTTP 临时故障在网络层重试；整轮失败在会话层重试；没钱和记忆塞满都不会被误当成网络抖动。

IMPLICATION

避免重复重试不可恢复错误，也让 compaction 接管真正的上下文问题。

L1factmodelContext

04 · 压缩阈值给输出预留固定预算，并尽量使用真实 usage

SOURCE FACT

默认 reserveTokens 为 16384，contextTokens 超过 contextWindow-reserve 才压缩。估算优先取最后 assistant usage 加尾随消息，缺失时用 chars/4，图片按近似字符成本处理。

PLAIN LANGUAGE

不会等输入把窗口完全塞满；先给回答留座位。能拿到模型账单就用真实 token，拿不到才用字符粗算。

IMPLICATION

比单纯按消息数量可靠，但固定 16k 对不同模型/任务可调性很重要。

L1factmodelContext

05 · cut point 不切 tool result，并支持拆分超长 turn

SOURCE FACT

算法从后往前保留 recentTokens，切点不会落在 tool result；若单回合太长可把 turn prefix 单独摘要、保留后段。summary 使用 Goal/Constraints/Progress/Decisions/Next Steps/Critical Context 结构并可迭代更新旧摘要。

PLAIN LANGUAGE

工具调用和结果不会被拦腰拆散；最近一个超长回合也不必全丢或全留，前半段概括、后半段保真。

IMPLICATION

上下文压缩保留执行连续性，结构化摘要便于后续 Agent 接棒。

L1factmodelContext

06 · overflow 最多压缩后自动重试一次，扩展可取消或替换摘要

SOURCE FACT

manual/auto compaction 都先触发 extension hook；扩展可取消或提供完整 compaction。overflow 路径移除错误消息后只重试一次，阈值型压缩不会无条件续跑，只有队列还有消息才继续。

PLAIN LANGUAGE

记忆爆仓会整理再试一次，不会反复总结到死；插件也能接管公司自己的摘要策略。

IMPLICATION

有明确的恢复上限和可插拔压缩策略。
