01 · 工具默认可并行，声明 sequential 或全局策略才串行

SOURCE FACT

同一 assistant message 的 tool calls 默认 Promise 并发；任一工具 executionMode=sequential 或配置顺序执行时改为串行。结果按原 tool call 顺序返回，before hook 可阻断，after hook 可改写结果、usage 和 terminate。

PLAIN LANGUAGE

互不冲突的工具一起跑更快；有副作用的工具可以声明排队。即使并发完成顺序不同，交给模型的账本仍按原顺序。

IMPLICATION

吞吐高，但自定义工具作者必须正确声明副作用和并发语义。

02 · 编辑采用唯一精确替换，并对同一文件串行化

SOURCE FACT

edit 要求 oldText 在文件中唯一且 replacement 不重叠，保留 BOM/行尾，写回后返回 diff/patch；同 canonical path 的 edit/write 进入 mutation queue，不同文件仍可并行。

PLAIN LANGUAGE

它不凭模糊相似度猜改哪里；目标文字必须只出现一次。同一文件上的两把手术刀要排队，避免互相覆盖。

IMPLICATION

机制简单可审计，面对漂移代码时会失败并要求模型重新读取。

03 · read 与 bash 使用不同方向的双阈值截断

SOURCE FACT

默认输出上限 2000 行或 50KB；read 保留头部并给 offset 续读提示，bash 保留尾部并把完整超长输出写入 /tmp/pi-bash-*.log。

IMPLICATION

减少工具输出占满上下文，同时维持可追溯性。
