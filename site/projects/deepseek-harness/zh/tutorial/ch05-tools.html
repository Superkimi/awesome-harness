01 · 工具调用先按 executionMode 分组

源码事实

executeToolCalls 先解析所有 tool-call，再按 executionMode 把连续 parallel 调用放进 bounded pool；遇到 exclusive 就形成 barrier。

白话解释

能并行的读操作一起做，可能冲突的写操作排队做。

对自研 Harness 的含义

并发策略应是工具声明的一部分，而不是模型临时决定。

02 · 工具结果异步完成，但按模型顺序提交

源码事实

runGroup 用 slots 保存完成结果，commitReady 只从连续可提交的 index 开始 finalize/finish、appendToolResult，并把 additionalContexts 放进下一步。

白话解释

第三个工具先完成也不能把第二个工具的回执顶到模型前面。

对自研 Harness 的含义

并发系统一定要有稳定 call id、提交序号和取消后的合成结果。
