METHOD

先看版本，再看调用链

每次项目更新都可能改变功能，所以本合集把 branch、commit、提交时间和 GitHub 行号写在页面上。教程中的‘它支持什么’必须能回到文件和行号；‘适合我们怎么借鉴’则单独标成迁移判断。横向矩阵用于定位路线，单项目报告用于逐条复核源码。

00 · SYNTHESIS

先给建设 Harness 的六条共同规律

01 · LOOP

循环决定上限

真正拉开差距的不是工具数量，而是 turn/step、取消、重试、回执和下一步决策有没有成为显式状态机。

02 · CONTEXT

上下文是工作台，不是 prompt 字符串

成熟实现会把检索、压缩、预算、快照、持久化和可重建性拆开；上下文越长，越需要事实源和淘汰策略。

03 · BOUNDARY

能力、策略、隔离必须分栏

MCP/插件是能力入口，approval/permission 是策略，sandbox/runner 才是执行隔离；把三者混在一起会制造虚假的安全感。

04 · EVIDENCE

版本锁定决定结论能否复核

每个单页都带 branch、commit、日期、文件和行号；历史账本与当前刷新源码分开标识，不把旧 finding 冒充 HEAD。

05 · COLLAB

子 Agent 要有交付物和预算

委派不是多开几个模型，而是独立 session、深度上限、取消、汇报、合并与失败语义。

06 · RECOVERY

恢复路径比 happy path 更能说明工程成熟度

事件日志、checkpoint、replay、幂等、压缩和回放测试决定系统断电、超时或工具失败后能不能接着做。

01 · BLUEPRINT

建议自研的需求交付闭环

把每个 Agent 放回一条完整交付链：入口不是终点，工具调用不是交付，知识回写才让下一轮变得更快。

02 · PROJECTS

26 条实现路线

01

MCP-first desktop/server harness

OpenWork

OpenWork 把桌面工作区、OpenCode 会话和 MCP Apps 组合成一个可观察的工作台；它的关键不是“能聊天”，而是把界面状态、会话路由、插件装配和沙箱边界做成可验证的协议。

技术分析 ↗小白教程 ↗11 findings · 51902a94b1d1
02

Local-first multi-agent cowork desktop

Eigent

Eigent 把单 Agent、Workforce、多模态工具、MCP 与本地记忆放进一个桌面 Cowork 工作流。源码里最值得学习的是任务锁、上下文构建、动作协议和跨重启记忆，而不是 UI 上的“多 Agent”按钮。

技术分析 ↗小白教程 ↗11 findings · 88d837f75ad9
03

Agent control plane with runtimes

Multica

Multica 把 Agent、Runtime、Task、Skill 和 Composio 工具放进一个可运维控制面。它的源码重点是资源生命周期：删除 runtime 前先处理绑定 Agent，任务与用量可查询，工具版本与连接账户显式传递。

技术分析 ↗小白教程 ↗11 findings · d467cc906915
04

Coding agent with microkernel and Compose

MiMo-Code

MiMo-Code 的源码把 Coding Agent 拆成 microkernel runtime、Compose 编排、插件工具、全局同步、权限和 context budget。它适合研究“内核保持稳定，能力从插件/技能/工作流注入”的工程路线。

技术分析 ↗小白教程 ↗11 findings · 332d7b0db65c
05

Local-first desktop agent with workflow graph

Kun

Kun 把 Direct 模式、Agent Graph、工作流运行时、扩展 API、权限和本地恢复放进一个桌面 Agent。它的核心学习点是：复杂任务不是多喊几个模型，而是把节点状态、取消、审批、恢复和插件契约做成一套运行时。

技术分析 ↗小白教程 ↗11 findings · 1377249652ce
06

Desktop agent with Tape, ACP, memory, and subagents

DeepChat

DeepChat 把对话运行时拆成 SessionTurn、Tape/Transcript、工具 effect、Memory lineage、ACP 与 Subagent slots。它特别适合学习“聊天产品如何升级成可恢复 Agent Harness”。

技术分析 ↗小白教程 ↗11 findings · d5e41ce0bb9e
07

Semantic diagram design skill

Diagram Design

Diagram Design 不是一个 Agent runtime，而是一套把语义模式、图形类型、复杂度预算、连接器规则和可访问性检查固化进 Skill 的 Harness。它是这批项目里最适合研究“如何让模型稳定产出技术图”的样本。

技术分析 ↗小白教程 ↗11 findings · 840f944f08be
08

Plugin-composed, event-sourced Coding Agent Harness

DeepSeek Harness

DeepSeek Harness 把 Agent 做成 Cordis 插件树：模型、工具、会话日志、权限、沙箱、Skill、子 Agent 和 UI 都是可替换服务。它最值得研究的不是某个工具，而是‘模型可见的一切必须可从事件日志重建’这条硬约束。
