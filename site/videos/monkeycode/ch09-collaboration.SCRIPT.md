1. 同事远程接手任务，我先确认谁能写、谁能看历史、实时流怎样交接。
2. 这一章不猜作者意图，只沿固定版本的运行时代码、契约和测试看事实。
3. 固定版本证据：backend/biz/task/handler/v1/task.go:323-384 · 远程协作以 owner write gate、历史回放和实时流为核心；backend/pkg/taskflow/types.go:626-640 · 平台层没有可见的子 Agent 调度与独立治理实体。
4. 事实一：旁观者能看直播，任务主人才能按按钮和继续对话；掉线重连后还能从历史接上。
5. 源码含义：它实现了人—Agent 远程接管，而不是多 Agent 共享计划或黑板。
6. 事实二：如果 Codex/OpenCode 内部自己再派子 Agent，MonkeyCode 目前只会把它们看成同一间 VM 里的同一项任务，无法逐个授权、暂停和计费。
7. 数据流：任务 → DB/VM/Redis → CLI 或 LLM proxy → MCP/权限 → 流、审计和交付。
8. 小白动作：先把任务状态拆成创建、启动、运行、失败、回收五个节点。
9. 第二个动作：把平台边界和 CLI 内层能力分开，记录谁负责权限、压缩和恢复。
10. 局限提醒：有多人只读/可写远程会话与问答；平台没有可见的独立子 Agent 调度控制面。
11. 这一章的结论：它实现了人—Agent 远程接管，而不是多 Agent 共享计划或黑板。
